# 规格书:ai-voice-chat 架构重构(迁往 pipecat)

> 状态:已拍板(2026-09-05,grill 四项决策完成)。本文件只回答"要解决什么问题、行为是什么",禁止出现代码。
> 任务拆分见 `docs/tickets-pipecat-refactor.md`。

## 1. 要解决的问题

1. **架构**:前端单文件承载全部交互逻辑(VAD/打断/切句/TTS 队列/播放/UI),服务端是无管线的四个独立 HTTP 接口,无法"按需取用功能块"。目标:换用官方 pipecat(Python)作为语音管线内核,模型以可插拔 service 的方式"抽象布线"接入,以后换/加模型只改 service 声明。
2. **打断漏字**(现存 bug,三个病灶):
   - a) 用户插话后的话轮占位是单槽,下一句会覆盖上一句,导致整句丢失;
   - b) 识别在途时用户再次开口,在途识别结果被直接作废,那句话凭空消失;
   - c) 打断确认前的几百毫秒里 AI 仍在播报,用户开头语音与 AI 残音混在一段送识别,叠加前补白偏短,导致开头几个字识别丢失。

## 2. 决策记录(grill 拍板)

| 决策 | 结论 |
|---|---|
| 技术路线 | 直接用官方 pipecat(Python)+ uv 管理;Node 侧只保留待迁移期共存,最终下线 |
| VAD 位置 | 留在浏览器(浏览器回声消除作用在采集层,防自打断最有效);服务端不再跑 VAD |
| 打断语义 | **智能打断**:短插话不打断(缓冲合并),持续语音超过阈值才打断;插话后 AI 思考继续、未播内容只显示不播报、新回答排队(沿用现有语义) |
| 自研代码语言 | TypeScript(前端);Python 侧全部类型标注 |

## 3. 目标架构(文字描述)

- **服务端(Python + FastAPI + pipecat)**:一个 WebSocket 承载会话(上行麦克风音频与客户端事件,下行合成音频与服务端消息),另保留少量 HTTP 兼容接口。管线按 pipecat 标准顺序组装:传输入口 → 语音识别 service → 用户话轮聚合 → 大模型 service → 语音合成 service → 传输出口 → 助手聚合。
- **模型接入矩阵**(全部做成 pipecat service,按配置选择,`auto`=本地就绪用本地、失败自动回退云端,语义与现状一致):
  - 识别:本地 sherpa-onnx SenseVoice(离线)/ 云端硅基流动;
  - 合成:本地 sherpa-onnx(matcha/vits,含增益、按句出音频、预热)/ 云端硅基流动 CosyVoice2;
  - 大模型:任意 OpenAI 兼容服务(Ollama / DeepSeek / OpenAI / 硅基流动),沿用现有 .env 配置项与"关闭思考"的语音场景约束。
- **前端(TypeScript 构建)**:浏览器只负责三件事——采集(带浏览器回声消除)+ 本地 VAD + 播放;UI 与现有页面一致。构建产物由 Python 服务托管。
- **共存与切换**:迁移期新旧服务并存(不同端口)便于对照验收;验收通过后由启动脚本统一切到新服务,旧 Node 服务代码下线。

## 4. 行为规格

### 4.1 语音问答(功能不变)
免点击:对着麦克风说话,静默判定后自动识别并回答;回答流式生成、逐句合成、边合成边播;状态提示(聆听/识别/思考/回答)与现在一致。

### 4.2 智能打断(修漏字)
- AI 播报时用户开口:
  - 短插话(时长低于阈值,如"嗯""等下"):**不打断**,该插话进入缓冲;若随后出现完整话语,缓冲内容与之一并识别;超时无后续则丢弃。阈值可配置,默认沿用现有"确认真实语音"的时长。
  - 持续语音(达到阈值):**打断**——立即停播报;AI 当前思考继续、未播完的文字只在页面显示不播报;新的完整话语到达即取消过期思考、立即回答最新话语。
- **漏字三条修法**(对应 1.2 的三个病灶):
  - 话轮占位从单槽改为**先进先出队列**,永不覆盖;
  - 在途识别结果**不再作废**,识别完成后照常入队;
  - 重叠段处理:**确认真实语音的当下就暂停 AI 音频**(短插话后来恢复播放,持续语音转为打断),把"AI 与用户声音重叠"的窗口从数百毫秒压到最小;不裁剪用户语音开头(裁剪会直接造成丢字);语音前补白适当加大,覆盖识别启动前的首音节。
- 自打断防护保持现状思路:扬声器漏音/短爆音判为误触发,不打断。

### 4.3 文字输入与历史会话(功能不变)
- 打字提问走完整打断(停播报 + 中止当前流),与现状一致。
- 历史会话:新建/加载/删除/自动保存/刷新恢复,数据格式与现有目录**完全兼容**(旧会话文件直接可读)。

### 4.4 兼容接口(skill 脚本依赖,行为不变)
- 录音上传识别:multipart 音频进、文本出;
- 文本合成:JSON 进、WAV 音频出,支持语速参数;
- 配置状态查询:返回实际生效的提供方,供页面显示。
- 现有 `/api/asr`、`/api/tts`、`/api/config` 的路径与请求/响应形态保持不变,skill 脚本零改动。

### 4.5 配置
现有 `.env` 全部配置项保留原含义(LLM/ASR/TTS、sherpa 模型路径与参数、人设 prompt、端口),新增项仅限:打断阈值、Python 服务端口、前端构建产物目录。启动/安装脚本改为拉起 Python 服务(uv 固定 Python 3.12,规避 3.14 轮子缺失)。

## 5. 非目标(本轮不做)

- 不做多用户/鉴权、不换 UI 框架、不改视觉设计;
- 不做服务端 VAD(留作以后可配置项);
- 不接入 agent/工具调用(日志里"接入 agent"是下一轮需求);
- 不做唤醒词(下一轮需求)。

## 6. 验收标准(用户视角)

1. 打开页面说话 → 听到回答,免点击、流式、逐句,延迟与现状相当或更好;
2. AI 播报时:说"嗯"等短音不打断;正常插话立即闭嘴;**连续插话/快速补话不丢任何一句**;插话后 AI 的新回答开头不缺字;
3. 打字提问、历史加载/删除/恢复与现状一致,旧会话文件可读;
4. `speak.ps1`、`listen.py` 零改动照常工作;
5. `npm run start/restart/stop` 拉起/重启的是新服务;本地离线与云端回退两种模式都能跑;
6. 独立会话 code review(12 坏味道清单)无未决问题。
