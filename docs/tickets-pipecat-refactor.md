# 任务拆分:pipecat 重构(按用户功能,非技术层)

> 实现顺序即编号;T1–T2 串行,T3–T5 依赖 T2,T6 收尾。

## T1 会话通路:浏览器 ↔ 新 Python 服务
**用户故事**:打开页面,状态栏显示"已连接新服务";我对麦克风说话,能在调试日志里看到音频上行、事件下行(此阶段还不回答,通路打通即可)。
- 包含:uv 工程骨架(pyproject、固定 Python 3.12)、WebSocket 会话端点、前端 TypeScript 构建链(esbuild,产物由新服务托管)、浏览器采集(16k 上行)与播放器(下行 PCM)、连接状态 UI;
- 验收:新旧服务并存可对照;刷新页面自动重连;断开服务时页面有明确提示。

## T2 语音问答:说完 → 听到回答
**用户故事**:免点击对话,说完自动识别并流式回答,逐句合成边收边播;本地离线/云端回退两种模式都可跑。
- 包含:sherpa STT/TTS service、硅基流动 ASR/TTS service、OpenAI 兼容 LLM service、`.env` 配置平移、服务启动预热、句级合成与播放队列、状态提示全链路;
- 验收:规格 4.1 + 验收 1、5;延迟与现状相当或更好;`/api/config` 能反映实际生效提供方。

## T3 智能打断 + 防漏字
**用户故事**:AI 说话时我"嗯"一声它不理我继续说;我正常插话它立即闭嘴;我快速连说两句,两句都被听到;新回答开头不缺字。
- 包含:客户端打断策略(短插话缓冲/合并/超时丢弃、持续语音打断)、重叠段音频截齐 + 前补白加大、话轮 FIFO 队列(不覆盖)、在途识别不作废、服务端打断传播(停合成不停思考)、误触发防护回归;
- 验收:规格 4.2 全部三条修法可演示;验收 2。

## T4 文字输入 + 历史会话
**用户故事**:打字提问立即得到回答;能新建/加载/删除历史,关掉浏览器再打开,对话还在;旧会话文件直接可读。
- 包含:文字输入通道(完整打断语义)、历史存取(兼容现有数据目录与格式)、自动保存/恢复、历史面板 UI;
- 验收:验收 3;旧 `data/` 会话文件加载成功。

## T5 skill 兼容接口
**用户故事**:`speak.ps1 "你好"` 能出声,`listen.py` 能出字,脚本一个字都不改。
- 包含:`/api/asr`(multipart)、`/api/tts`(wav、语速)、`/api/config` 兼容层,行为与旧接口一致;
- 验收:验收 4;两个脚本实测通过。

## T6 切换与下线
**用户故事**:`npm run start/restart/stop` 拉起的就是新服务;安装脚本能在一台新机器上装好(uv + Python 3.12 + 依赖 + 前端构建)。
- 包含:start/stop/restart/install 脚本改写、`.env.example` 更新、README/开发文档更新、旧 Node 服务代码与依赖下线(确认无回归后删除);
- 验收:验收 5;新机安装脚本 dry-run 通过;仓库里不再有两套服务。
